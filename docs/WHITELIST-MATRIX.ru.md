# Доступ к семейному Matrix при белых списках

Проверено 10 октября 2026 года. Цель — переписка и фотографии в обычном Element без VPN на телефонах родных. Технически дополнительный HTTPS-вход возможен. Доступность его IP и TLS-имени в ограниченной сети остаётся отдельным условием: покупка CDN сама по себе её не обеспечивает.

Практический первый вариант — CDN перед существующим доменом Matrix с полностью отключённым кешированием API и авторизации. Прямой Serverless Container из прежнего конспекта для обычного Element не подходит. Развёртывание облачных ресурсов и изменения домашней сети в рамках этого исследования не выполнялись.

## Исправления прежнего конспекта

| Утверждение в конспекте от 25 сентября | Актуальная оценка |
|---|---|
| Любой IP Яндекса и любое имя `*.yandexcloud.net` проходят | Это гипотеза. Разрешённый сервис не означает разрешение всей инфраструктуры его поставщика. Проверять нужно конкретные IP, имя, оператора и место |
| Containers прозрачно передаст Matrix Bearer и cookies | Прямой HTTPS-вызов удаляет `Authorization` и `Cookie`. До nginx они не доходят |
| Containers лучше Functions для фотографий | Лимит запроса **и ответа** Containers — 3,5 МБ вместе с заголовками. Ограничены также скачивание и большие ответы синхронизации |
| Yandex CDN сразу пропускает все методы | POST, PUT, PATCH и DELETE по умолчанию закрыты; возможность включения согласуется с поддержкой |
| Для Containers нужен `/sync timeout=3000` | У Containers нет CDN-лимита 5 секунд. Обычный запрос допускает до 10 минут; больше — режим долгоживущего контейнера |
| Семья наверняка поместится в бесплатные вычисления | Ожидание long-poll тоже занимает оплачиваемое время экземпляра; малое число вызовов не означает малую стоимость |
| Ручной homeserver URL исключает все обращения к дому | MAS публикует отдельные адреса issuer, входа и обновления токенов. Они не меняются вслед за base URL |
| RST на произвольный SNI доказывает фильтрацию оператором | RST или TLS alert может прислать сам сервер. Нужна та же проверка из свободной сети и корректный сервер для выбранного имени |
| Уведомления и звонки невозможны при любых вариантах | При недоступном APNs фоновые уведомления iPhone ненадёжны. HTTP-прокси не переносит TURN, но разрешённый TURN/TLS-хост — отдельная техническая возможность |

Пример официального перечня оператора: [МТС](https://moskva.mts.ru/personal/belyj-spisok-servisov). Он не обещает доступ ко всем пользовательским ресурсам облачных поставщиков.

Источники ограничений: [вызов Containers и фильтрация заголовков](https://yandex.cloud/ru/docs/serverless-containers/concepts/invoke), [лимиты Containers](https://yandex.cloud/ru/docs/serverless-containers/concepts/limits), [FAQ CDN](https://yandex.cloud/ru/docs/cdn/troubleshooting). Старые числа разрешённых IP, универсальные заявления о DNS и сроке жизни обхода не следует использовать как установленные факты.

## Что требуется именно этому Matrix

Для сервера с Synapse и Matrix Authentication Service проверить фактический discovery:

- `https://example.com/.well-known/matrix/client` и объявленный homeserver;
- `https://matrix.example.com/_matrix/client/versions`;
- используемый клиентом `auth_metadata` endpoint;
- `/auth/.well-known/openid-configuration`, включая issuer, authorize, token, registration и keys.

Hostname в примерах — плейсхолдер. Согласованный клиентский вход должен обслуживать и Matrix API, и авторизацию.

Если изменить только homeserver на яндексовый адрес, вход через браузер и обновление токенов всё ещё потребуют домашний hostname. Подмена issuer в одном JSON не решает проблему: OIDC требует согласованного issuer, а MAS использует канонический публичный адрес. Простое переписывание HTML, redirects и cookies не является надёжным способом получить второй issuer. [Конфигурация MAS](https://matrix-org.github.io/matrix-authentication-service/reference/configuration.html), [правила OpenID Connect Discovery](https://openid.net/specs/openid-connect-discovery-1_0.html).

Поэтому сохранение `matrix.example.com` при переносе его клиентского входа на CDN — наиболее щадящий путь. MXID, база и ключи шифрования остаются прежними. Необходимое условие — оператор пропускает этот hostname на адресах CDN. Доступ только к собственному сервисному домену провайдера, если он обнаружится, потребует отдельного пилота с каноническим адресом MAS и проверкой сессий. Переключать рабочую авторизацию семьи до такого пилота нельзя. Well-known также нельзя считать исключённым навсегда: discovery, повторный вход и поведение конкретного клиента нужно проверять; `server_name` участвует в discovery и федерации, хотя отличается от base URL.

Нужно проверить весь клиентский маршрут: Matrix API, `/auth/*`, discovery, Element Web при использовании браузера, загрузку и скачивание медиа, thumbnails и ключи E2EE. Garage остаётся хранилищем за сервером; редиректы на домашний S3 или другой недоступный hostname нельзя оставлять в клиентском пути. Федерация не обязана идти через этот вход. [Matrix Client Server API](https://spec.matrix.org/latest/client-server-api/).

Element X использует sliding sync: не ограничиваться старым GET `/sync`. Проверять реальные GET и POST запросы используемой версии клиента. Если фронт ждёт источник только 5 секунд, обычный long-poll нужно адаптировать на origin с запасом, включая sliding sync, либо выбрать фронт с большим ожиданием. Не все таймауты находятся в query-параметре. [Simplified Sliding Sync](https://github.com/matrix-org/matrix-spec-proposals/blob/main/proposals/4186-simplified-sliding-sync.md).

## Сравнение входов

| Вход | Для сообщений и фото | Решение для первого опыта |
|---|---|---|
| Yandex CDN | Возможен после разрешения методов, проверки Bearer/cookies и адаптации ожидания origin 5 секунд | Кандидат, если поддержка разрешит Matrix API и адрес проходит в нужной сети |
| Selectel CDN | POST/PUT/PATCH/DELETE включаются в панели. Остальные свойства Matrix нужно проверить | Удобный кандидат для пилота без ожидания включения методов поддержкой |
| Beget CDN | Методы записи включаются через поддержку, есть сервисный поддомен | Недорогой кандидат после подтверждения методов, TLS и времени ожидания |
| CDNvideo | Есть услуги доставки HTTP-контента; условия динамического API уточнять отдельно | Резервный кандидат, а не доказанный доступ при белых списках |
| VK Cloud, Beeline, Timeweb, NGENIX и другие | Название поставщика не доказывает доступность пользовательского ресурса | Не покупать несколько услуг без сетевого измерения и проверки API |
| Yandex Containers напрямую | Удаляет Bearer и Cookie, лимит 3,5 МБ в обе стороны | Отклонить как прозрачный вход для штатного Element |
| Yandex API Gateway с HTTP integration | Можно явно передать методы, headers и query; лимит 2,5 МБ в обе стороны | Пилот текста и маленьких файлов, не основной маршрут семейных фото |
| VM с nginx/Caddy | Наиболее полный контроль, нормальный long-poll и крупные медиа | Технический запасной вариант, если доступность конкретного IP и SNI подтверждена |

Источники: [Selectel HTTP methods](https://docs.selectel.ru/cdn/content/http-methods/), [Beget настройка CDN](https://beget.com/ru/kb/manual/cdn), [CDNvideo HTTP](https://doc.cdnvideo.ru/Services_setup/http/), [API Gateway HTTP integration](https://yandex.cloud/ru/docs/api-gateway/concepts/extensions/http), [его лимиты](https://yandex.cloud/ru/docs/api-gateway/concepts/limits).

Для API Gateway отсутствие явного forwarding query может потерять `since` и другие параметры. Сохранять повторяющиеся параметры, все нужные заголовки и путь, а также Cookie/Set-Cookie авторизации. Для Containers варианты с кастомным заголовком вместо Bearer требуют адаптации клиента или дополнительного фронта; штатный Element этого автоматически не делает. Переносить access token в URL ради такого обхода не следует.

## Пилот без перенастройки телефонов родных

Первый этап — отдельный тестовый вход и тестовые аккаунты. Порядок позволяет прекратить опыт до переноса семейных сессий.

1. Выбрать один CDN и подтвердить поддержку штатных PUT/POST, Bearer, Cookie/Set-Cookie, отключения кеша, CORS и нужных размеров медиа. Для проверки фронта использовать безопасный echo-origin: он возвращает только наличие заголовков и размеры, не реальные токены.
2. Получить реальный HTTPS-адрес ресурса и проверить его в обычной сети. Сравнить DNS, TCP и TLS для этого же адреса в ограниченной мобильной сети. VPN выключен, Wi-Fi выключен. Успешное открытие `ya.ru` не заменяет проверку ресурса.
3. Проверить сохранение текущего Matrix hostname на CDN. Если SNI не проходит, не переносить production DNS; исследовать второй канонический вход отдельно.
4. На тестовых аккаунтах пройти вход и refresh, отправку сообщений в обе стороны, E2EE и проверку устройств, отправку и получение фото. Использовать файлы 1, 3, 5 и 10 МБ, сравнить SHA-256 скачанного шифротекста. Проверить историю после длительного отсутствия, разрыв сети и повторное подключение.
5. Выполнить те же действия в изолированной лабораторной сети с запрещёнными прямыми обращениями к дому. Только после успешного результата — небольшой тест в реальной ограниченной сети.
6. Для миграции сохранить текущий hostname, учесть apex discovery и остальные используемые адреса; обеспечить возможность вернуть DNS. В штатном Element нельзя рассчитывать на автоматический перебор произвольных запасных homeserver URL.

Ориентир трудозатрат: 1–2 рабочих дня на первый технический прототип после включения нужных методов; несколько дополнительных дней на MAS, Element X/iOS и медиа при необходимости смены hostname. Ожидание реального окна ограничений в эту оценку не входит. Это оценка работы, не обещание срока получения доступа.

## Как симулировать ограничения

Симуляция нужна для поиска забытых зависимостей. Она не воспроизводит закрытые настройки оператора и не доказывает доступность CDN на мобильной сети.

Стенд — отдельная VM или отдельный Wi-Fi-шлюз, клиент подключён только к нему. Основной OpenWRT и домашние маршруты не менять. Для iPhone отключить сотовые данные, VPN и Private Relay на время опыта, чтобы не было обходного маршрута.

| Режим стенда | Правила | Что обнаруживает |
|---|---|---|
| IP ограничения | Разрешить DNS стенда и TCP 443 к фактическим адресам тестового CDN, остальное запретить | Прямые обращения к дому, S3, авторизации, сторонней статике; отдельно учесть IPv6 |
| IP и SNI | Дополнительно разрешить только имена входа в TLS ClientHello | Зависимость от текущего домена или сервисного домена провайдера |
| Проблемная связь | Добавить задержку/потери и разрывы соединения | Восстановление sync, повтор отправки, загрузку файлов |
| Нет пушей | APNs/FCM вне разрешённого набора, приложение затем открыть вручную | Получение накопившихся сообщений без уведомления |

Для SNI-фильтра на отдельном стенде подходит TLS passthrough proxy с чтением ClientHello без расшифровки. HTTP/3 блокируется для явной проверки TCP-варианта; отдельным запуском проверяется реальная политика QUIC. Снимать журнал DNS и отклонённых соединений, без access tokens и содержимого сообщений. Меняющиеся CDN IP обновлять по DNS, не оставлять одну случайную A-запись навсегда.

Контрольные условия: прямой домашний endpoint недоступен, обычный неразрешённый сайт недоступен, тестовый CDN доступен; у двух тестовых аккаунтов сообщения приходят в обе стороны и медиа совпадает после скачивания. Вход и refresh должны работать при тех же правилах. Отдельно проверять уже открытую сессию и вход с чистого клиента.

В реальном тесте достаточно собственной SIM того же оператора в нужном регионе во время ограничений. Французская SIM в роуминге может иметь другой маршрут. Если своей SIM там нет, участие родных нужно лишь для короткой итоговой проверки. Ответ 401/404 от нашего тестового HTTPS-ресурса уже доказывает достижимость пути, но не работу всего Matrix.

## Надёжность и пределы

На CDN отключить кеширование API, `/auth/*` и аутентифицированных медиа, включая кеш ошибок и выдачу старого контента при отказе origin. Одного изменения cache key недостаточно. Проверить два аккаунта на одном URL. TLS проверять до origin, не отключать верификацию. Не отправлять через новый вход административные API.

CDN завершает TLS и получает клиентские bearer-токены и метаданные. E2EE чатов сохраняется между устройствами, но это не делает токены и все остальные ответы безопасными для общего кеша. Не менять доверенные forwarded headers вслепую и не закрывать существующий публичный origin так, чтобы сломать федерацию или прямой резервный доступ.

Пуши iPhone зависят от APNs, а работа приложения в фоне ограничена iOS. Если APNs недоступен, рассчитывать на открытие Element пользователем. Это не доказательство, что Apple блокируется в каждом режиме ограничений. [Сетевые требования APNs](https://support.apple.com/en-gb/102266).

Для текста и медиа не нужен TURN. Звонки требуют отдельного доступного медиамаршрута: HTTP CDN не становится TURN-сервером. TURN/TLS может работать, если его конкретный адрес и порт разрешены, однако проверку звонков нельзя заменить успешным Matrix HTTPS-запросом.

Домашний интернет, электричество и сам Synapse остаются зависимостями. CDN не продолжит доставку новых сообщений при падении origin. Два CDN могут зависеть от одной сети или одинаково блокироваться; их независимость проверяется. Для срочной семейной связи сохранить обычный телефон/SMS как резерв: обещать постоянную доступность Matrix при любой политике сети нельзя.

## Что даёт прикреплённый репозиторий

[whitelists_bypass](https://github.com/frank-underwood64/whitelists_bypass) описывает VLESS/XHTTP через CDN. Полезна идея доступного HTTP-входа и проверок каждого слоя. Она не доказывает работу обычного Matrix: Xray-клиент умеет менять транспорт, методы и упаковку данных, штатный Element этого не умеет. Даже текущий текст репозитория ставит условие доступности выбранных узлов в конкретной сети. Платные инструкции и обобщённые обещания не заменяют тесты нашего адреса.

Начать стоит с одного проверяемого CDN-пилота, сохраняя домен и авторизацию. Для бюджета разумно рассматривать Beget по расходу трафика либо Selectel за 550 ₽/месяц, выбирая по сетевой доступности и подтверждённой совместимости. Яндекс остаётся кандидатом после согласования методов записи; прямой Containers исключён. VPN — отдельный будущий опыт и не требуется для этого пилота.
